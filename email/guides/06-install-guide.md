# Getting set up — the team guide

You don't need to install anything technical to work with the Sunless campaign system. There are just three things to have ready — a website to bookmark, a GitHub login, and Claude — and this guide walks through each one in plain language.

## The three things you'll use

| What | What it's for | Where |
|---|---|---|
| The Studio | See every campaign, email, playbook and guide — always up to date | [www.jimmycoco.email](https://www.jimmycoco.email) |
| GitHub | The company's master filing cabinet — view any source file in your browser | [github.com/mattrogerspro/jimmycoco](https://github.com/mattrogerspro/jimmycoco) |
| Claude | Where you ask for campaigns and content, in ordinary English | [claude.ai](https://claude.ai) |

## Step 1 · Bookmark the Studio

Open [www.jimmycoco.email](https://www.jimmycoco.email) and bookmark it. Nothing to install — it's a website. Everything lives in five sections: **Overview** (what's live right now), **Playbooks** (the brand rules), **Sequences** (every campaign's timeline), **Live emails** (exactly what customers receive), and **Help & guides** (where you're reading this).

Every page has a **Copy link** button — use it to send a colleague the exact campaign, email or guide you're looking at.

## Step 2 · Accept your GitHub invitation

You'll receive an email invitation to the repository. Accept it, create a free account if you don't have one, and you're done. You only ever need to **view** files there — click any link and read it in the browser. You never need to download anything, and please don't edit files directly on GitHub; changes go through the process in Step 4 so nothing skips review.

## Step 3 · Get Claude ready

Sign in at [claude.ai](https://claude.ai) with your work account. The company uses a Claude skill called **build-jimmy-coco-email-campaign** — think of it as Claude having read every brand rule before you say a word. If it's not already available on your account, ask the administrator to add it. That's the whole setup.

## Step 4 · Make your first request

Ask Claude for what you want the way you'd brief a colleague:

> Build a five-email onboarding campaign for Manchester salons.

> Draft three subject line options for the Sydney campaign's second email.

Claude reads the brand playbooks, writes the campaign, builds the emails and hands back a draft for human review. Two guides are worth reading before your first request: **Start here — requesting a campaign** and the **Prompt library** (both in this Help & guides section).

Three things to always remember:

- **Nothing you request ever sends an email.** Every draft needs named human approval, and the send system is separately locked.
- **Never state prices, discounts or delivery promises unless they're confirmed.** If you don't know, say so — the system marks them for approval rather than guessing.
- **The playbooks win.** If anything Claude produces looks off-brand, say so — the rules in Playbooks are the source of truth.

## What you can safely ignore

Hosting, databases, sending infrastructure, API keys — all of that is set up once by the administrator and isn't your job. If a report mentions Vercel, Resend or Supabase, that's background reading, not something you need to touch.

## If something isn't working

Studio won't load, GitHub says you don't have access, or Claude doesn't seem to know the brand rules — contact the administrator (Matt) rather than trying to fix it yourself. It's a five-minute fix on his side.
